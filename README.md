# Бот «Альфа-Курс»

Telegram-бот: отвечает по базе знаний «Альфа-Курс», задаёт один уточняющий вопрос на слишком общий запрос,
честно говорит «в базе нет», собирает профиль кнопками и ведёт напоминания (в т.ч. налоговые даты).

## Запуск (одна команда)
```bash
cp env.example .env   # впишите TELEGRAM_BOT_TOKEN (и BASE_URL сайта)
docker compose up -d --build
```
- **Бэкап** положите в `data/alfa_course_hackathon.backup` (путь меняется через `BACKUP_FILE`). Он восстанавливается один раз при первой инициализации тома `pgdata`; чтобы восстановить заново: `docker compose down -v`.
- **Env** (`env.example`): `TELEGRAM_BOT_TOKEN`, `BASE_URL` (из него строятся ссылки `BASE_URL/<раздел>/<slug>`; пока `example.com`), `POSTGRES_PASSWORD`, `BOT_TZ` (по умолчанию Europe/Moscow), `BACKUP_FILE`.
- **Порты**: наружу ничего не публикуется. Бот сам ходит в Telegram (long polling), Postgres доступен только внутри сети compose (`db:5432`).
- Логи: `docker compose logs -f bot`. Индекс поиска (`bot.kb_items`) строится при первом старте, ~1500 материалов.

## Тесты
```bash
docker compose exec bot python -m pytest tests
```

## Сценарий проверки (вручную в Telegram)
1. «квантовая физика банан» → честное «в базе ничего не нашёл», без слабых совпадений.
2. «налоги» → один уточняющий вопрос с кнопками; затем «для ИП на УСН» → ссылки на статьи со сниппетом.
3. «УСН на маркетплейсах» → есть платный курс (цена и ссылка), без пересказа содержания; повторный вопрос подряд платный курс не предлагает (не чаще раза в 5 ответов).
4. После 2-го ответа — профиль кнопками (этап, сфера, режим), можно «Пропустить».
5. `/tax` → выбор режима (УСН ИП / УСН ООО / НПД) → подписка на нужные даты → кнопки «За 1/3/7 дн.» меняют частоту, «Отключить» выключает.
6. `/remind напомни завтра в 9 оплатить аренду`, `/list`, `/del N`, `/pause`, `/resume`.

## Ограничения
- Поиск лексический (Postgres full-text), без LLM: не понимает синонимы и сложные формулировки; интерфейс `SearchBackend` позволяет подключить семантический бэкенд позже.
- Налоговые даты ориентировочные, без переноса на выходные и без региональных особенностей; патент и ОСН пока не поддержаны.
- Ссылки ведут на `BASE_URL` — до получения реального адреса они заглушки.
- Одна таймзона на всех (`BOT_TZ`); напоминания проверяются раз в 30 секунд.
- Платные курсы: текст уроков используется только для релевантности и никогда не показывается.

## План проверки влияния на конверсию и возврат на платформу
**Гипотеза:** бот с честными ответами, платными рекомендациями «по делу» и напоминаниями повышает долю пользователей, дошедших до курса, и возвращает их на платформу.

**Дизайн (A/B):** новые пользователи Telegram случайно (по хешу `tg_id`) делятся 50/50: тест — бот с рекомендациями курсов и напоминаниями; контроль — бот только с ответами по базе (без рекомендации платных курсов и без напоминаний). Рандомизация на входе, группа фиксируется. Длительность — до набора выборки под минимально детектируемый эффект (посчитать по базовой конверсии платформы, α=0.05, мощность 0.8), не менее 4 недель, чтобы поймать налоговый цикл.

**Метрики:**
- Основная: конверсия в покупку курса за 30 дней (клик по ссылке на курс с UTM `utm_source=tgbot&utm_campaign=<группа>` → покупка на платформе).
- Возврат: доля вернувшихся на сайт по ссылкам бота в 7/30 дней, число повторных сессий на платформе, CTR ссылок на материалы.
- Вовлечённость: вопросы на пользователя, retention бота D7/D30, доля создавших напоминание, доля оставивших профиль.
- Защитные: доля «в базе нет» (качество покрытия), отписки и `/pause`, жалобы; рост покупок не должен идти за счёт падения удовлетворённости.

**Анализ:** сравнение долей двумя пропорциями (z-тест/хи-квадрат) с доверительным интервалом разницы; срезы по этапу, сфере, режиму. Решение: выкатываем, если основной эффект статистически значим, а защитные метрики не ухудшились.

**Ограничения плана:** атрибуция покупки требует UTM и связи аккаунта бота с аккаунтом платформы (или когорты по меткам); мало платных курсов (сейчас один), поэтому основной упор — на возврат на платформу и клики, а не на покупки.

## Устройство
- `bot/kb.py` — индекс (`bot.kb_items`) и поиск за интерфейсом `SearchBackend` (сейчас Postgres full-text, `russian`);
  LLM- или векторный бэкенд можно подключить, не трогая диалог.
- `bot/dialog.py` — логика ответов: уточнение, «не нашёл», платный курс не чаще раза в 5 ответов и без показа текста уроков.
- `bot/reminders.py` — разбор фраз, расписание, налоговый календарь (даты ориентировочные, без переноса на выходные).
- `bot/main.py` — aiogram, команды `/remind /tax /list /del /pause /resume`.
